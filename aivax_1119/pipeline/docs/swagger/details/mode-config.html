AIVAX Pipeline · 실행 모드와 전역 필터 설정

mode.json

/etc/aivax/mode.json

Pipeline의 Inline/Mirror 실행 모드와 필터별 활성화 여부를 정하는 JSON 파일이다.

일반 검사는 요청 목록과 전역 설정을 함께 확인한다. filter_list에 이름을 넣어도 해당 필터의 enabled=false이면 실행하지 않는다. 반대로 enabled=true여도 요청 목록에서 제외한 필터는 실행하지 않는다.
설정 예제설정 필드필터 대응표 실행 조건생략·오류 처리변경 적용

설정 예제

다음은 Inline에서 정규식·첨부파일 검사를 켜고 SLM·SecuXper를 끈 예제다. 운영 파일의 실제 값이나 기본 설정을 보여주는 것은 아니다.

{
  "schema_version": 2,
  "mode": "inline",
  "updated_at": "2026-10-19T00:00:00Z",
  "source": "manual",
  "filters": {
    "regex": { "enabled": true },
    "multimodal": { "enabled": true },
    "slm": { "enabled": false },
    "secuxper": { "enabled": false }
  }
}

기본 파일 경로는 /etc/aivax/mode.json이다. AIVAX_PIPELINE_MODE_FILE로 다른 파일을 지정할 수 있다. 상대 경로를 지정하면 Pipeline 루트 디렉터리를 기준으로 해석한다.

설정 필드

필드타입생략 시설명
schema_version정수2설정 형식 버전. 현재 1과 2를 지원한다. true/false는 버전 값으로 허용하지 않는다.
mode문자열inlineinline 또는 mirror. 앞뒤 공백을 제거하고 소문자로 변환한 뒤 검증한다.
updated_at문자열1970-01-01T00:00:00Z설정 변경 시각 메타데이터. Z 또는 UTC 오프셋을 포함한 ISO 날짜·시간을 사용한다. 이 값이 바뀌어도 자동 재로딩하지 않는다.
source문자열default설정을 작성한 주체나 경로를 나타내는 메타데이터. 공백만 있는 문자열은 허용하지 않는다. 실제로 읽을 파일 경로를 바꾸는 필드가 아니다.
filters객체필터별 기본값regex, multimodal, slm, secuxper의 전역 활성화 설정. 필요한 항목만 지정할 수 있고 생략한 필터에는 기본값을 적용한다.
filters.<종류>.enabled불리언아래 대응표 참고해당 일반 검사 실행 허용 여부. JSON true/false만 허용하며 문자열 "true"/"false"나 정수 1/0은 허용하지 않는다.

inline과 mirror

inline은 검사와 로그 처리를 수행한 뒤 최종 판정을 응답한다. mirror는 빈 action/0으로 즉시 접수하고 백그라운드에서 일반 검사를 수행한다. Mirror의 백그라운드 검사에도 같은 filters.*.enabled와 요청 목록 조건을 적용한다.

Mirror에서는 CSO 선행 검사와 동의 전용 분기를 적용하지 않는다. debug=true여도 즉시 응답에는 디버그 필드를 추가하지 않는다.

설정 키와 API 필터 이름

mode.json의 설정 키와 요청의 filter_list 값은 서로 다르다.

mode.json 설정filter_list 값생략 기본값검사 순서·역할
filters.regex.enabledsecret_filtertrue1. 정규식 정책 검사.
filters.multimodal.enabledfile_block_filtertrue2. 첨부파일 멀티모달 검사.
filters.slm.enabledslm_filtertrue3. SLM 정책 검사.
filters.secuxper.enabledsecuxper_filterfalse4. SecuXper 정책 검사. 활성화 시 별도 접속·인증 설정과 정책 준비도 필요하다.

input_filter는 입력 로그 저장 요청이며 검사 필터가 아니다. 대응하는 filters.input_filter 설정은 없다.

multiple_filter의 검사 대상 선택

일반 검사 실행 후보는 요청 목록에 포함 + 전역 enabled=true + 검사 구현 준비를 모두 만족해야 한다. 활성화 설정은 실행 여부를 정하며, 요청 배열 순서나 중복으로 고정 검사 순서를 바꿀 수 없다.

요청 목록에 포함enabled결과
예true검사 구현이 준비돼 있으면 실행 후보가 된다. 앞 필터에서 block이 발생하면 후속 검사는 실행하지 않을 수 있다.
예false요청했어도 실행하지 않는다. 요청만으로 전역 비활성화를 우회할 수 없다.
아니오true전역 활성화돼 있어도 요청에서 제외하면 실행하지 않는다.
아니오false실행하지 않는다.

filter_list를 생략하면 기본 다섯 이름을 모두 요청하므로, 그중 전역 활성화된 일반 검사만 실행 후보가 된다. [] 또는 null이면 일반 검사 대상은 없다. 알 수 없는 필터 이름은 전역 설정과 관계없이 HTTP 404다.

예제 설정에 요청을 조합하면

위 예제에서 ["input_filter", "secret_filter", "file_block_filter", "slm_filter", "secuxper_filter"]를 요청하면 일반 검사 후보는 정규식과 첨부파일이다. SLM과 SecuXper는 전역 비활성화 상태라 실행하지 않는다. ["slm_filter"]만 요청해도 SLM을 강제로 실행하지 않는다.

CSO·동의·로그 처리와의 관계

Inline의 CSO 선행 검사는 AIVAX_PIPELINE_CSO_ENABLED로 별도 활성화하며 filter_list나 이 파일의 일반 필터 설정으로 끄지 않는다. CSO가 차단하면 일반 필터로 진행하지 않는다.

Inline의 활성화된 동의 요청은 CSO를 통과한 뒤 일반 필터를 생략한다. 일반 필터를 모두 꺼도 input_filter에 따른 입력 로그 저장 요청은 유지되며, CSO 차단 로그 같은 별도 로그 처리 경로도 남는다. 전역 비활성화된 일반 필터는 디버그 filter_result에서도 제외한다.

생략과 잘못된 설정의 처리

filters 전체나 개별 필터를 생략하면 정규식·첨부파일·SLM은 true, SecuXper는 false를 사용한다. 따라서 SLM을 사용하지 않으려면 "slm": { "enabled": false }를 명시한다.

필터 항목을 작성했다면 내부에는 enabled 불리언 하나가 필요하다. filters.secret_filter처럼 요청 이름을 설정 키로 쓰거나, enabled를 문자열로 쓰거나, 알려지지 않은 필터 키를 넣으면 유효하지 않은 설정이다.

파일 읽기·JSON 파싱이 실패하거나 설정 검증에 실패하면 Pipeline은 경고 로그를 남기고 전체 기본 설정을 사용한다. 잘못된 필터 한 항목만 제외하는 방식이 아니다. 기본 모드는 inline이고 기본 필터 값은 위 대응표와 같다.

변경 적용

  1. 실제 설정 파일 경로를 확인한다. 기본은 /etc/aivax/mode.json이며 경로 재정의 여부도 확인한다.
  2. 원하는 filters.<종류>.enabled를 JSON 불리언으로 수정하고 문법을 확인한다.
  3. Pipeline 프로세스를 재시작한다. 여러 worker를 사용하면 모든 worker에 새 설정을 적용한다.

설정 어댑터는 파일을 한 번 읽어 프로세스 메모리에 캐시한다. 파일 저장이나 updated_at 수정만으로 실행 중인 Pipeline에 즉시 반영되지 않는다. 정책 갱신 API도 이 파일을 다시 읽는 명령이 아니다.

현재 Pipeline 구현 기준. 이 페이지는 설정 설명이며 서버의 실제 설정 파일을 조회하거나 수정하지 않는다.
