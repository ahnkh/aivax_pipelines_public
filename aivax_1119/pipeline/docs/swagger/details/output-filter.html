output_filter

POST /v1/filter/output_filter

실제 AI 응답을 INPUT과 같은 연결 키로 전달해 분석 로그를 병합한다.

성공 응답은 최종 OpenSearch 반영 완료를 뜻하지 않는다. 현재 out_result는 항상 빈 객체다.
처리 흐름요청 필드응답 필드 JSON 예제오류

처리 흐름과 연결 키

  1. multiple_filter 응답의 message_id를 보존한다.
  2. 실제 AI 응답을 llm_output에 넣어 Content-Type: application/json으로 요청한다.
  3. Pipeline은 같은 message_id의 INPUT과 OUTPUT을 병합한다. OUTPUT이 먼저 도착해도 병합 저장소에서 INPUT을 기다릴 수 있다.
  4. 최종 문서는 로그 전달 경로를 거쳐 OpenSearch에 반영된다. 이 API의 성공만으로 최종 반영 완료를 판단하지 않는다.

입력 API와 다른 처리

OUTPUT은 ID 앞뒤 공백을 제거하지만 빈 ID를 자동 생성하지 않는다. 일반 요청은 DTO가 빈 ID를 허용하더라도 INPUT과 연결하려면 실제 ID를 전달해야 한다.

user_id, email, ai_service, client_host의 null을 유지한다. 입력과 달리 IP를 정규화하지 않으며, ai_service=null의 로그 표시명은 빈 문자열이다. 세션 ID는 내부 모델에 전달하지만 기본 출력 로그 빌더는 저장하지 않는다.

저장 옵션

llm_output은 빈 문자열을 허용한다. 출력 저장 설정에 따라 전문 저장을 생략하거나 길이를 제한할 수 있으며, 기본 한도는 UTF-8 200,000바이트다. 기본 출력 로그의 모델·지연시간·토큰 사용량은 계산하지 않는다.

사용자 동의와 저장 실패

true 또는 문자열 on/1/true/yes/enable/enabled는 명시적 동의 출력이다. 문자열은 앞뒤 공백과 대소문자를 무시한다. 동의 출력의 빈 ID는 HTTP 422다.

일반 출력의 저장 실패 반환값은 HTTP 실패로 바꾸지 않지만, 명시적 동의 OUTPUT의 비성공 저장 반환값은 HTTP 503으로 처리한다. 별도 예외가 전파되는 경우는 HTTP 오류 명세를 따른다. 동의 INPUT이 있으면 OUTPUT에 동의 플래그를 다시 보낼 필요는 없다.

요청 필드

모든 필드에 기본값이 있다. 정의되지 않은 추가 키는 기본적으로 무시한다. 서비스 ID는 고정 enum으로 제한하지 않는다.

성공 응답과 필드

OUTPUT은 out_result 래퍼를 유지하며 현재 값은 {}다. debug=true 또는 동의 출력에서도 동일하다. final_decision, filter_result, log_evidence를 추가하지 않는다.
